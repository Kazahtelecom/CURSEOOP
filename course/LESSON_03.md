## 1. Вспоминаем — 5 минут

В прошлой теме ReadingList хранил объекты Book. Теперь представь, что ты слушаешь аудиокниги и тоже хочешь хранить их в своём списке.

Подумай:

- что есть и у книги, и у аудиокниги;
- какие данные есть только у обычной книги;
- какие данные есть только у аудиокниги.

Обычно у обоих материалов есть название. У книги есть автор, у аудиокниги может быть рассказчик и длительность.

## 2. Ищем общее — 10 минут

Можно было бы добавить в список отдельную коллекцию для книг и отдельную для аудиокниг. Но тогда каждый поиск и каждый вывод пришлось бы писать дважды.

Вместо этого опишем общее понятие ReadingMaterial — материал для чтения или прослушивания. У него будет название и метод description().

Книга и аудиокнига являются материалами. Поэтому они могут унаследовать общее поведение и добавить собственные подробности.

## 3. Базовый класс — 15 минут

Вот общий класс:

    class ReadingMaterial:
        def __init__(self, title):
            self.title = title

        def description(self):
            return "Материал: " + self.title

Класс, от которого наследуются другие, называют базовым. Его также можно назвать родительским. Он хранит общие данные или поведение.

Книга становится видом ReadingMaterial:

    class Book(ReadingMaterial):
        def __init__(self, title, author):
            super().__init__(title)
            self.author = author
            self.is_read = False

        def description(self):
            return "Книга: " + self.title + " — " + self.author

        def mark_as_read(self):
            self.is_read = True

В скобках после имени Book указан базовый класс. Вызов super().__init__(title) просит базовый класс сохранить название. Книга добавляет автора и статус прочтения.

В этой теме мы расширяем знакомый Book, добавляя ему базовый тип. Данные книги и её методы остаются.

## 4. Переопределяем метод — 10 минут

У аудиокниги есть рассказчик, поэтому ей нужна своя версия описания:

    class AudioBook(ReadingMaterial):
        def __init__(self, title, narrator):
            super().__init__(title)
            self.narrator = narrator

        def description(self):
            return "Аудиокнига: " + self.title + ", читает " + self.narrator

Метод description() уже есть у базового класса. В AudioBook мы определили метод с тем же именем, чтобы получить подходящее для аудиокниги описание. Это называется переопределением.

## 5. Одна команда для разных объектов — 10 минут

Создадим обычную книгу и аудиокнигу:

    paper_book = Book("Дюна", "Фрэнк Герберт")
    audio_book = AudioBook("Матильда", "Кейт Уинслет")

    materials = [paper_book, audio_book]
    for material in materials:
        print(material.description())

Ожидаемый результат:

    Книга: Дюна — Фрэнк Герберт
    Аудиокнига: Матильда, читает Кейт Уинслет

Цикл не выясняет, книга перед ним или аудиокнига. Он вызывает один и тот же метод description(), а каждый объект выполняет подходящую версию. Такое поведение называют полиморфизмом.

Пока можно запомнить простой смысл: разные объекты отвечают на одинаковый вызов каждый по-своему.

## 6. Наследование или композиция? — 10 минут

Сравним две связи:

- Книга — это материал. Это отношение «является», поэтому подходит наследование.
- ReadingList содержит книги и аудиокниги. Это отношение «содержит», поэтому подходит композиция.

Полезная проверка: если объект можно естественно описать словами «является видом», наследование может подойти. Если он хранит или использует другой объект, обычно подходит композиция.

Наследование не нужно добавлять только ради повторного использования строк кода. У подкласса должно быть понятное отношение к базовому классу.

## Выходной билет

1. Что общего у Book и AudioBook?
2. Какой метод переопределяет AudioBook?
3. Почему ReadingList содержит эти объекты, а не наследуется от Book?

**Самопроверка:** оба имеют название и описание; AudioBook переопределяет description(); список содержит коллекцию материалов, а сам не является книгой.
