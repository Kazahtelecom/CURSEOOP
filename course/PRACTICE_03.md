# Практика 3. Книга и аудиокнига в одном списке

**Неделя:** 3  
**Встреча:** практика, 60 минут  
**Перед началом:** пройди [лекцию 3](LESSON_03.md).  
**Нужно:** Python 3 и редактор кода.

## Цель

Создать обычную книгу и аудиокнигу так, чтобы у них был общий метод description(), но каждое описание подходило своему виду материала. Обработать оба объекта одним циклом.

## 1. Разогрев — 5 минут

Определи вид связи:

- Book является ReadingMaterial.
- ReadingList содержит Book.

Первое отношение — «является видом», значит, можно рассмотреть наследование. Второе — «содержит», значит, это композиция.

## 2. Создаём общий класс — 12 минут

Напиши базовый класс:

    class ReadingMaterial:
        def __init__(self, title):
            self.title = title

        def description(self):
            return "Материал: " + self.title

Он пока хранит только то, что есть у разных видов материалов: название. Метод description() задаёт общий способ получить описание.

## 3. Обновляем Book — 13 минут

Измени знакомый класс так, чтобы Book наследовался от ReadingMaterial:

    class Book(ReadingMaterial):
        def __init__(self, title, author):
            super().__init__(title)
            self.author = author
            self.is_read = False

        def mark_as_read(self):
            self.is_read = True

Добавь свою версию description():

    def description(self):
        return "Книга: " + self.title + " — " + self.author

Важно: методы должны иметь отступ внутри класса Book. super().__init__(title) сохраняет название в общей части.

Проверь:

    dune = Book("Дюна", "Фрэнк Герберт")
    print(dune.title)
    print(dune.description())

Ожидаемый результат:

    Дюна
    Книга: Дюна — Фрэнк Герберт

## 4. Добавляем AudioBook — 10 минут

Создай класс аудиокниги:

    class AudioBook(ReadingMaterial):
        def __init__(self, title, narrator):
            super().__init__(title)
            self.narrator = narrator

        def description(self):
            return "Аудиокнига: " + self.title + ", читает " + self.narrator

Аудиокнига получает название от базового класса и хранит своего рассказчика. Она переопределяет description(), чтобы вернуть подходящую строку.

Создай объект и проверь результат:

    matilda = AudioBook("Матильда", "Кейт Уинслет")
    print(matilda.description())

## 5. Один цикл для обоих видов — 10 минут

Собери список и напиши функцию:

    materials = [dune, matilda]

    def describe_all(items):
        for item in items:
            print(item.description())

    describe_all(materials)

Функция не проверяет, какой перед ней класс. Она просит каждый объект выполнить description().

Ожидаемый результат:

    Книга: Дюна — Фрэнк Герберт
    Аудиокнига: Матильда, читает Кейт Уинслет

Добавь вызов dune.mark_as_read() и проверь, что описание продолжает работать. Отметка о прочтении осталась у Book и не мешает общему методу.

## 6. Проверяем и исправляем — 6 минут

Посмотри на ошибочную версию:

    class AudioBook(ReadingMaterial):
        def __init__(self, title, narrator):
            self.title = title
            self.narrator = narrator

Она может работать, но повторяет присваивание названия, которое уже умеет делать базовый класс. Исправь её: вызови super().__init__(title). Так общее поведение остаётся в одном месте.

Проверь все три примера:

- Book сохраняет название и автора;
- AudioBook сохраняет название и рассказчика;
- describe_all работает с обоими объектами и не проверяет их тип.

## 7. Выходной билет — 4 минуты

1. Что общего у Book и AudioBook?
2. Какой метод у них работает по-разному?
3. Почему describe_all не нужно менять, если список содержит оба вида?

**Самопроверка:** у обоих есть название и description(); подклассы дают разный результат этого метода; функция вызывает общий метод у каждого объекта.

Проверь, что список содержит три вида объектов и каждый выводит своё описание. В конце объясни, почему EBook является ReadingMaterial и зачем списку общий метод.
