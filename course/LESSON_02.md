## Цель

Понять, как один объект может хранить и использовать другие объекты. К концу встречи ты сможешь объяснить, почему список чтения отвечает за список книг, а каждая книга — за собственное название и статус.

## 1. Вспоминаем — 5 минут

Вспомни класс Book из прошлой недели:

    class Book:
        def __init__(self, title, author):
            self.title = title
            self.author = author
            self.is_read = False

        def mark_as_read(self):
            self.is_read = True

Коротко ответь:

1. Что хранит одна книга?
2. Что изменяет вызов book.mark_as_read()?
3. Если создать две книги, будут ли у них отдельные названия?

Если ответ не сразу приходит в голову, вернись к примеру. Повторение помогает закрепить материал.

## 2. Кто за что отвечает? — 10 минут

Представь, что у тебя уже двадцать книг. Книга знает своё название, автора и статус. Но какой объект должен хранить все книги и искать непрочитанные?

Мы создадим ReadingList — список чтения. У него своя ответственность:

- хранить коллекцию книг;
- добавлять книгу;
- возвращать список непрочитанных книг;
- считать, сколько книг осталось прочитать.

Книга не должна искать себя среди остальных. Она отвечает за данные одной книги. ReadingList отвечает за работу с набором книг.

| Объект | За что отвечает |
| --- | --- |
| Book | Данные одной книги и её статус |
| ReadingList | Набор книг и поиск по этому набору |

## 3. Список содержит книги — 15 минут

Когда один объект хранит другие объекты и использует их, это называют композицией. Здесь ReadingList содержит объекты Book.

Начнём с пустого списка:

    class ReadingList:
        def __init__(self):
            self.books = []

Знак [] создаёт пустой список Python. Каждая новая ReadingList получает свой отдельный список книг.

Добавим метод:

    def add_book(self, book):
        self.books.append(book)

Метод принимает объект книги и кладёт его в список. Мы передаём сам объект, а не только название: тогда список сможет обратиться и к автору, и к статусу.

## 4. Ищем непрочитанные книги — 10 минут

Добавим метод, который возвращает непрочитанные книги:

    def unread_books(self):
        result = []
        for book in self.books:
            if not book.is_read:
                result.append(book)
        return result

Проследи по строкам:

1. Создаём пока пустой результат.
2. По очереди смотрим на каждую книгу.
3. Если книга ещё не прочитана, добавляем её в результат.
4. Возвращаем найденные книги.

Слово not означает «не». Поэтому not book.is_read означает «книга ещё не прочитана».

## 5. Предсказываем результат — 10 минут

Прочитай пример и сначала предскажи вывод:

    dune = Book("Дюна", "Фрэнк Герберт")
    matilda = Book("Матильда", "Роальд Даль")

    books = ReadingList()
    books.add_book(dune)
    books.add_book(matilda)
    dune.mark_as_read()

    print(len(books.books))
    print(len(books.unread_books()))

Ожидаемый вывод:

    2
    1

В списке две книги. Первая отмечена прочитанной, поэтому непрочитанной остаётся одна.

Важное наблюдение: ReadingList хранит ссылки на те же объекты Book. Когда мы отмечаем dune прочитанной, список видит её обновлённый статус.

## 6. Выходной билет — 10 минут

Объясни своими словами:

1. Почему у ReadingList есть собственный атрибут books?
2. Почему статус is_read хранится у Book, а не один общий статус у списка?
3. Что вернёт unread_books(), если список пустой?

**Самопроверка:** список хранит коллекцию; каждая книга знает свой статус; для пустого списка вернётся пустой список.
